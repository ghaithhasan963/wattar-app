# خطة تنفيذ Wattar — M0 → M10
**التاريخ:** 2026-11-14 · **المرجع الأعلى:** `المطلوب تماما .txt` (٣٦ قسماً) · **أدلة التدقيق:** `AUDIT_FINDINGS_2026-11.md` · **سجل الأهداف:** `DEVELOPMENT_ROADMAP.md`

> هذه هي الخطة التي نمشي عليها. كل مرحلة مرتبطة بأقسام محددة من الملف، ولها بوابة قبول لا تُتجاوَز.
>
> **قاعدة القبول:** لا شيء يُعدّ منجزاً لأن الواجهة ظهرت أو لأن APK بُني. يُعدّ منجزاً عند تسجيل: الحساب، الجهاز، الخطوات، النتيجة. وإن لم أستطع إثباته أكتب «محجوب» ولا أدّعي النجاح.
>
> **قاعدة النقاش:** لا نبدأ أي مرحلة قبل أن نتناقش في أقسامها وقراراتها. القرارات المعلّقة في القسم ٨ لا تُنفّذ قبل موافقتك.

### توجيهات المدير (GH_tec) — ثابتة حتى إشعار آخر

| # | التوجيه | الأثر على الخطة |
|---|---|---|
| 1 | **صفر تكاليف حتى الإطلاق** | كل الخدمات على الطبقات المجانية: Supabase Free، LiveKit Cloud ضمن حدّه المجاني، FCM، GitHub Actions، استضافة اللوحة المجانية، بلا نطاق مدفوع. أي بند يتطلب دفعاً أتوقف وأستشيرك قبل أي خطوة. |
| 2 | **إطلاق أساسي كامل، لا إطلاق تجريبي** | لا Beta ولا «نسخة تجريبية» للجمهور. عند الإطلاق يجب أن تكون كل الأنظمة داخل النطاق مكتملة ومختبرة. بناءات الاختبار الداخلية ليست إطلاقاً ولا تُسمّى إطلاقاً. |
| 3 | **لا عمل غير مطلوب** | أي شيء لم يُطلب صراحة أستشيرك فيه أولاً. لا تحسينات جانبية، لا إعادة هيكلة، لا ملفات أو أنظمة إضافية بلا أمر. |
| 4 | **البدء بكلمة صريحة** | لا أبدأ أي مرحلة حتى تقول «اشتغل». وقبلها أعرض عليك ما سأفعله بالضبط. |
| 5 | **التوقف عند الحاجة** | أي قرار أو سر أو صلاحية أو حساب أو التزام مالي أرجع لك فيه وأتوقف، ولا أفترض نيابة عنك. |

**نتيجة مباشرة على الخطة:** M0.9 وM10.6 وM10.9 تعمل بمبدأ «مجاني أولاً»، وحدود الطبقات المجانية تُقاس وتُوثّق في M0 قبل أي تصميم تخزين أو بنية. مرحلة التوسع المدفوع تبدأ **بعد** الإطلاق وبقرار منك، وليست جزءاً من هذه الخطة.

## 0) كيف نعمل فعلياً

| الخطوة | من ينفّذها | الأثر |
|---|---|---|
| تعديل الكود | أنا على جهازك | لا أثر خارجي |
| `tsc` + `deno check` + الاختبارات | أنا | يمنع دفع كود مكسور |
| commit + push إلى `master` | بموافقتك | يشغّل بناء APK |
| بناء APK | GitHub Actions | Artifact صالح ٧ أيام |
| تطبيق SQL | أنت من لوحة Supabase، أو أنا بموافقتك وبنسخة احتياطية | يغيّر القاعدة |
| نشر Edge Functions | `deploy-functions.ps1` (يحتاج جلسة Supabase على جهازك) | يغيّر سلوك الخادم |
| تحديث الأسرار | أنت فقط، لا تُرسل القيم | — |

**الـ push لا يفعل ثلاثة أشياء:** لا يشغّل SQL، ولا ينشر الدوال، ولا يعدّل الأسرار.

**الفروع (مؤكد 2026-11-14):** النشر على الفرع الأساسي `master` (هو الافتراضي على GitHub). المراحل الخطرة (M2، M3، M4، M5، M7) تُنفّذ على `dev-<اسم>` ثم PR **فقط إذا طلبت ذلك**؛ وإلا مباشرة على `master` مع بوابة الفحص.

**OneDrive:** المشروع داخل مجلد متزامن. أنصح باستثناء `node_modules` و`.git` من المزامنة أو نقل المشروع لمسار خارج OneDrive. غير عاجل لكنه يمنع أعطالاً غامضة.

## 1) قواعد بيننا

1. دفعة واحدة في كل مرة: إصلاح أو نظام جديد، لا خلط.
2. لا SQL على الإنتاج بدون: migration مرقّم + نسخة احتياطية + موافقتك.
3. لا أسرار في المحادثة ولا في المستودع.
4. كل دفعة تُغلق بسطر في `DEVELOPMENT_ROADMAP.md`: التاريخ، ما تغيّر، نتيجة الاختبار.
5. الملف المالي والتاريخ المالي لا يُحذف ولا يُعاد كتابته. التصحيح بقيود عكسية.
6. لا فيديو، لا عائلات، لا PK، لا بيانات وهمية.
7. لا دفع إلى GitHub بدون كلمتك، لأن كل دفع يستهلك بناء.

## 2) صورة الوضع الحالي (مؤكدة بالكود)

| النظام | الحالة الحقيقية |
|---|---|
| المصادقة | بريد + OTP هاتف + Google + وكيل بالهاتف. التسجيل معطّل عملياً (SMTP غير مضبوط، تأكيد البريد معطّل) |
| الغرف والصوت | مبنية بالكامل (LiveKit، مقاعد، شات، كتم، إجراءات مالك، حضور). الصوت يعمل عندك. **الشات والمقاعد تُكتب من العميل بهوية محلية** |
| المحفظة | `balance_gold` + `balance_diamond` + `balance_diamond_promo` + `balance_converted_coins` + `game_points` — أي ٥ أرصدة، والملف يريد عملتين |
| Ledger | جدول `wallet_transactions` موجود، بلا قيد مزدوج ولا مطابقة ولا قيود عكسية |
| الشحن والسحب | شحن يدوي USDT + سحب Diamond. الحالات السبع غير مكتملة |
| الألعاب | ٥ ألعاب كاملة على الخادم مع RTP قابل للضبط وفرض نتيجة إداري |
| المجتمع | أصدقاء، متابعة، رسائل مدفوعة، حظر، بلاغات، قصص، منشورات، إشعارات + Push |
| المضيفات/الوكلاء | تقديم واعتماد ومجموعات وكلاء ولوحة وكيل — بلا عقود ولا أهداف |
| VIP/LV | خطط عضوية + XP موجودان، بلا تدرّج VIP ١–١٠ ولا منحنى LV ١–١٠٠ |
| الإدارة | ٢١ ملف صفحة (١٩ تشغيلية + دخول/استعادة) + سجل تدقيق + RBAC جزئي — بلا إدارة موظفين كاملة ولا تسوية رصيد |
| التخزين | رفع عام + upsert بلا حدّ حجم، بلا ضغط ولا مصغّرات |
| الجودة | صفر اختبارات، صفر lint، CI يبني APK فقط بعد `tsc` للتطبيق |
| الإصدار | APK release موقّع بـ`debug.keystore` — غير صالح للتوزيع الحقيقي |
| المخطط | ٣٥ ملف `patch_*.sql` مطبّقة يدوياً بترتيب غير موثّق + ٣ نسخ مكررة من المخطط |

## 3) الفجوات بثلاث طبقات

### أ) إصلاح (النظام موجود لكنه معطوب أو خطر)
تسجيل معطّل · شات/مقاعد مكتوبة من العميل · سعر الرسالة من العميل · كلمة مرور غرفة نص صريح وغير مستخدمة · `recover-password` بلا حماية · تدقيق يرسل before/after كاملة للمتصفح · حقن PostgREST في بحث المستخدمين · عمليات مالية بضغطة واحدة بلا سبب · سجلات عالقة في `reviewing` · تعيين تذاكر يُكتب فوق التعيين · تلف JSONB · Dice يعرض RTP محلياً · Slots يعلّق · إعادة تحميل كاملة عند كل Realtime · APK موقّع بمفتاح debug.

### ب) استكمال (موجود ناقص)
Ledger بلا قيد مزدوج ولا مطابقة · تسوية رصيد إدارية · حالات شحن/سحب كاملة · عقود وأهداف مضيفات · VIP ١–١٠ كتدرّج · منحنى LV · تأثيرات هدايا متقدمة · Leaderboard بلا واجهة · إدارة موظفين وأدوار · لوحة وكيل بلا طلبات تمويل وتقارير · إشعارات بلا حملات · i18n غائب · RTL غير مفعّل · إدارة أجهزة وجلسات.

### ج) غير موجود إطلاقاً
المدير الثاني للغرفة · تدخل الوكالة داخل غرف مضيفاتها · أدوات الحماية المدفوعة · عقود المضيفات · تقييد حسب الدولة + Feature Flags · RBAC بخمسة أدوار · قيود Ledger المزدوجة · العقوبات والاعتراضات · فلترة الكلمات وRisk Scoring · ملصقات وهدايا داخل المحادثة · معرض صور بدل المنشورات · حملات وعروض · مكافآت LV · إطارات وتأثيرات VIP · ضغط صور ومصغّرات وCDN.

العائلات/العشائر · تحديات PK · أي فيديو (غرف، مكالمات، قصص) · نشر المتاجر الآن · أي اشتراك أو سيرفر أو نطاق مدفوع قبل الإطلاق · أي إطلاق تجريبي أو Beta.
