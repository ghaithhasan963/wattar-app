# 🚀 Wattar — دليل التشغيل السريع

> من صفر إلى تطبيق يعمل في أقل من 15 دقيقة

## الخطوة 1: إنشاء Supabase (5 دقائق)

1. اذهب إلى [supabase.com](https://supabase.com) وسجّل حسابًا مجانيًا
2. اضغط **New Project** → أدخل اسمًا (مثل `wattar`) → اختر كلمة مرور → أنشئ
3. بعد جاهزية المشروع، افتح **SQL Editor** (أيقونة `>_` من القائمة الجانبية)
4. افتح الملف `wattar-docs/wattar_schema.sql` → انسخ كل محتواه → الصقه في SQL Editor → اضغط **Run**
5. افتح `wattar-docs/patch_profile_editing.sql` ونفّذه بعد المخطط الأساسي. ينشئ دالة آمنة لتعديل الملف الشخصي، وفهرسًا لأسماء المستخدمين، وحاوية الصور وسياسات رفع الصور. إذا أوقف الفحص التنفيذ بسبب أسماء مستخدمين مكررة، عالج التكرارات أولًا ثم أعد تشغيل الملف.
6. بعد نجاح تعديل الملف الشخصي، افتح `wattar-docs/patch_social_foundation.sql` ونفّذه. يجهز البحث عن الأعضاء وطلبات الصداقة والمحادثات الخاصة والحظر/الإبلاغ ودعوات الغرف وتحديات النرد المجانية الثنائية والرباعية وإدارة رموز الإشعارات، مع سياسات RLS وRealtime. لا تعرض ميزات المجتمع للمستخدمين قبل تطبيق هذا التعديل.
7. نفّذ `wattar-docs/patch_wattar_v2_social.sql` بعد الملفين السابقين. يضيف تأكيد العمر ونقاط اللعب والقصص ومجموعات الوكلاء، وتجهيز إخفاء بيانات الحساب وحذف وسائطه عند طلب الحذف. اختبره أولًا على قاعدة اختبار، ولا تطبّقه على الإنتاج قبل مراجعة النسخة الاحتياطية.
8. نفّذ `wattar-docs/patch_user_onboarding_privacy.sql` بعد ترحيل المجتمع. يضيف الجنس المطلوب وخيار الملف العام/للأصدقاء، ويتحقق من بلوغ 18 عامًا داخل قاعدة البيانات من دون الاحتفاظ بتاريخ الميلاد. يعرض الملف الخاص اسم المستخدم الضروري لإرسال طلب صداقة، لكنه يخفي الاسم الظاهر والصورة والنبذة وحالة الاتصال عن غير الأصدقاء. هذا تحقق ذاتي للعمر فقط وليس توثيق هوية. لا ترفع صور هوية إلى Wattar قبل اختيار مزود KYC، وتحديد البلدان وسياسة الخصوصية والاحتفاظ. اختير مبدئيًا مزود خارجي؛ يذكر [توثيق Sumsub](https://docs.sumsub.com/docs/supported-documents-and-countries) دعم وثائق من 220+ بلدًا وإقليمًا، وليس كل دولة، لذا يجب التحقق من تغطية كل سوق ومن شروط الحساب التجاري قبل الدمج.

   ملاحظة دمج Sumsub: [وحدة React Native الرسمية](https://docs.sumsub.com/docs/react-native-module) تتطلب إعدادات أصلية في Android وiOS، ومنها مستودع Maven وKotlin 1.9.25 على Android، وCocoaPods وiOS 13+ وأوصاف استخدام الكاميرا/الصور/الموقع على iOS. لا يثبت الدليل الذي راجعناه دعم Expo Go أو يوفر إضافة Expo رسمية؛ المسار المقترح للاختبار هو Development Build مخصص، مع التحقق من توافق إعدادات Expo الحالية قبل اعتماد الدمج. قائمة البلدان في الموقع ليست تأكيدًا لتوفر مستنداتك أو تفعيل الخدمة لحسابك. لا تضع مفاتيح Sumsub في التطبيق؛ أنشئ رموز SDK من خادم موثوق، وأضف التحقق من توقيع Webhook بعد اختبار Sandbox وإقرار الأسواق وسياسة الخصوصية والاحتفاظ.
9. نفّذ `wattar-docs/patch_wattar_v2_wallet.sql` بعد ترحيل المجتمع. ينشئ وسائل الشحن وطلبات الشحن وتسوية الهدايا.
10. نفّذ `wattar-docs/patch_wattar_v2_wallet_economy.sql` بعد ترحيل المحفظة. يفصل Coins المدفوعة والمحوّلة عن Diamonds القابلة للسحب والترويجية، ويضيف مخزون الوكيل المدفوع مسبقًا وطلبات السحب الذرّية.

    اخترت قيمًا افتتاحية للاختبار فقط: 1000 Coins لكل دولار، و1 Coin محوّلة لكل Diamond، و1000 Diamonds لكل دولار، وحد أدنى للسحب 10000 Diamond. الشحن والسحب مغلقان افتراضيًا، وكل وسيلة شحن غير مفعّلة؛ لا تفتحها إلا على مشروع اختبار وبعد إعداد معلومات الدفع. راجع هذه الأسعار وحسابات الأرصدة القديمة قبل أي تشغيل حقيقي.
11. نفّذ `wattar-docs/patch_store_missions.sql` بعد ترحيل اقتصاد المحفظة. يضيف مهمات يومية يتحقق تقدمها من سجلات الخادم، ومكافآتها نقاط لعب مجانية وXP فقط، ويتيح للإدارة إدارة كتالوج الهدايا بأسعار ونسب مقيدة ومسجلة في السجل. واجهة المتجر تستخدم تسوية الإهداء الذرية.
12. لإضافة Slots، نفّذ `wattar-docs/patch_slots_enum.sql` وحده أولًا وانتظر نجاحه، ثم نفّذ `wattar-docs/patch_slots_game_config.sql` في استعلام منفصل. اللعبة تستخدم نقاطًا مجانية فقط، ويُحسب ناتج الجولة على الخادم.
13. بعد اكتمال جميع الترحيلات، نفّذ `wattar-docs/patch_admin_audit_controls.sql`. يحصر قراءة سجل الإدارة في المسؤولين النشطين، ويسجل إنشاء وتعديل وحذف إعدادات المنصة والألعاب ووسائل الشحن والغرف والهدايا والمهمات، ويجعل إيقاف المستخدم أو حظره الدائم إجراءً ذريًا يتطلب سببًا ويسجله في السجل.
14. ترحيل المحفظة ينشئ حاوية `deposit-proofs` الخاصة وسياساتها. من **Storage** أنشئ فقط الحاويات الإضافية غير المنشأة:
   - `gift-icons` → Public ✅
15. من **Authentication → Providers** عطّل تسجيل الدخول المجهول (Anonymous sign-ins). إزالة زر الضيف من التطبيق لا تكفي إذا بقي المزود مفعّلًا في Supabase.
16. احفظ هذه القيم من **Settings → API**:
   - `Project URL` (مثل: `https://abc123.supabase.co`)
   - `anon public key`

## الخطوة 2: إنشاء حساب الأدمن (2 دقيقة)

1. من القائمة: **Authentication → Users → Add user → Create new user**
2. أدخل البريد وكلمة مرور قوية وفريدة، ثم فعّل **Auto Confirm** إذا كان الحساب لك. لا تضع كلمة المرور في الكود أو SQL أو المحادثات.
3. ينشئ المخطط ملفًا في `public.users` تلقائيًا. انسخ `User UUID` من حساب Auth.
4. ارجع لـ **SQL Editor** وارفع صلاحية هذا الحساب فقط (استبدل UUID والبريد):

```sql
UPDATE public.users
SET role = 'super_admin'
WHERE id = 'ضع-ال-UUID-هنا'
  AND email = 'البريد@الإلكتروني';

SELECT id, email, role, status
FROM public.users
WHERE id = 'ضع-ال-UUID-هنا';
```

تأكد أن التحديث طال صفًا واحدًا وأن نتيجة الاستعلام تعرض `super_admin` وحالة `active`، ثم سجّل الدخول إلى لوحة الإدارة. إذا لم يظهر صف، تأكد من تشغيل المخطط الأساسي ومن تطابق UUID والبريد.

## الخطوة 4: تشغيل لوحة الأدمن (2 دقيقة)

```bash
cd wattar-admin

# إنشاء ملف البيئة
cat > .env.local << 'EOF'
VITE_SUPABASE_URL=ضع-Supabase-URL-هنا
VITE_SUPABASE_ANON_KEY=ضع-Anon-Key-هنا
EOF

npm install
npm run dev
```

افتح المتصفح على `http://localhost:5174` وسجّل دخول بحساب الأدمن ✅

### نشر لوحة الإدارة على الإنترنت (بدون localhost)

ملف `wattar-admin/vercel.json` يضبط رجوع المسارات الداخلية إلى تطبيق React حتى تعمل صفحات مثل `/users` و`/reset-password` بعد النشر.

1. أنشئ مشروعًا في Vercel واربط مستودع المشروع، أو استخدم Vercel CLI من مجلد `wattar-admin`.
2. اضبط **Root Directory** على `wattar-admin`، وأمر البناء `npm run build`، ومجلد الناتج `dist`.
3. أضف متغيري البيئة التاليين في إعدادات Vercel لكل بيئة تريد تشغيلها:
   - `VITE_SUPABASE_URL` = رابط مشروع Supabase الحقيقي.
   - `VITE_SUPABASE_ANON_KEY` = المفتاح العام (anon/publishable) فقط.
4. انشر المشروع، واختبر رابط Vercel `https://<project>.vercel.app` من الهاتف عبر شبكة الهاتف، لا من رابط localhost.
5. في Supabase → **Authentication → URL Configuration → Redirect URLs** أضف رابط إعادة تعيين كلمة المرور:
   `https://<project>.vercel.app/reset-password`
   واستبدله بعنوان النشر الفعلي. عند إضافة نطاق مخصص لاحقًا، أضف رابط النطاق المخصص أيضًا.

لا تضع `service_role` أو أسرارًا في إعدادات لوحة الويب. رابط Vercel المجاني يكفي للاختبار العام؛ شراء نطاق مخصص اختياري، ويتطلب ضبط DNS في شركة النطاق.

## الخطوة 5: تشغيل تطبيق المستخدم (3 دقائق)

```bash
cd wattar-app

# يستخدم المشروع Node.js 22.22.0 أو أحدث.
# يحتوي .npmrc إعداد حلّ الاعتماديات اللازم للتثبيت المتوافق مع القفل.

# إنشاء ملف البيئة
cat > .env << 'EOF'
EXPO_PUBLIC_SUPABASE_URL=ضع-Supabase-URL-هنا
EXPO_PUBLIC_SUPABASE_ANON_KEY=ضع-Anon-Key-هنا
EOF

npm install

# لأن الغرف تستخدم LiveKit ومكونات أصلية، لا تستخدم Expo Go.
# ابنِ APK اختبار Android بمعماريات React Native الافتراضية:
eas build -p android --profile preview
```

يتضمن APK الاختبار معماريات Android الافتراضية بدل حصره على ARM64، ليعمل على نطاق أوسع من الأجهزة. الحد الأدنى المحدد حاليًا هو Android 7.0 (API 24)؛ لذلك لن يثبت على أجهزة أقدم من ذلك. لا يمكن ضمان كل طراز أو إصدار نظام دون اختباره فعليًا.

يدعم المشروع Android وiOS. لبناء نسخة iPhone استخدم `eas build -p ios --profile production` ثم وزّعها عبر TestFlight؛ تثبيت نسخة iOS مباشرةً يتطلب إعداد Apple Developer وتسجيل الأجهزة عند اختيار التوزيع الداخلي. لا يمكن بناء أو اختبار نسخة iPhone من APK Android.

يُطلب إذن الميكروفون بعد تهيئة الحساب على Android، وعلى iOS عند محاولة التحدث لأول مرة. لا يطلب التطبيق إذن الإشعارات عند التشغيل؛ يطلبه فقط عند تفعيل الإشعارات من الإعدادات. اختيار الصور يطلب إذن الصور وقت استخدام الميزة؛ رفض الإذن لا يمنع استخدام بقية التطبيق.

صفحة المجتمع تشمل البحث وطلبات الصداقة والمحادثات الخاصة ودعوات الغرف وتحديات النرد المجانية. إظهار متصل الآن تقريبي حسب نبضة نشاط التطبيق كل دقيقة. مؤشر الكتابة والقراءة يعملان عبر Realtime بعد تطبيق التعديل. لتلقي Push، فعّل الإشعارات من الإعدادات على جهاز الحساب المستقبِل؛ لا يشترط تفعيلها على جهاز المرسل. يجب أن تكون دالة `social-push` منشورة وأن يكون رمز الجهاز مسجلًا في قاعدة البيانات.

لإيصال Push على Android:
1. في Firebase Console أنشئ تطبيق Android بالمعرّف `app.wattar.mobile` ونزّل `google-services.json` إلى جذر مجلد `wattar-app`؛ يشير إعداد Expo إلى `./google-services.json`.
2. في Firebase Console → **Project settings → Service accounts** أنشئ مفتاح حساب خدمة FCM V1. ارفعه إلى Expo/EAS من إعدادات بيانات اعتماد Android؛ لا تضع ملف مفتاح حساب الخدمة في المشروع أو المحادثة.
3. أنشئ APK Android جديدًا وثبّته على جهاز حقيقي. افتح **الإعدادات → الإشعارات** على جهاز المستلم وفعّلها؛ يطلب Wattar إذن النظام وقت التفعيل، ولا يطلبه عند تشغيل التطبيق. يجب تفعيل الإشعارات على جهاز المستلم فقط.
4. أرسل طلب صداقة أو رسالة من جهاز آخر. تسجيل Google منفصل عن إعداد Firebase/FCM.

لن تعمل الإشعارات على بناء الويب. منح إذن النظام وحده لا يكفي دون ملف Firebase الخاص بتطبيق Android، واعتماد FCM V1 في Expo/EAS، ونشر دالة `social-push`.

تحتاج Edge Function `livekit-token` إلى إعادة نشر بعد تحديثها حتى يتمكن المدعو إلى الغرفة الخاصة من الحصول على رمز الصوت. أعد نشر الدالة من مجلد `wattar-functions` بعد تطبيق تعديل قاعدة البيانات.

## إعداد تسجيل الدخول

- يتيح التطبيق التسجيل بالبريد وكلمة المرور والهاتف وGoogle وFacebook، لكن توفر الزر لا يعني أن المزود مضبوط على الخادم. في فحص 2026-11-07 كان البريد مفعّلًا والتأكيد التلقائي معطلًا، والهاتف وGoogle وFacebook غير مفعّلة. أكد صاحب المشروع لاحقًا إعداد البريد وGoogle، وأبقى Facebook والهاتف مؤجلين. أعد اختبار إعدادات Supabase عند تغييرها؛ يحتاج تأكيد البريد إلى SMTP صالح لإيصال الرسائل.
- لتفعيل Google وFacebook، فعّل كل مزود في **Authentication → Sign In / Providers** وأدخل Client ID وClient Secret من حساب المطور الخاص بالمزود. لا ترسل أسرار المزود أو مفاتيح Supabase في المحادثات.
- عنوان إعادة التوجيه الذي يجب إضافته داخل إعدادات كل مزود هو:
  `https://vczyjbqixqzositlkfkn.supabase.co/auth/v1/callback`
- أضف `wattar://callback` إلى قائمة **Authentication → URL Configuration → Redirect URLs** في Supabase. هذا هو مسار شاشة `app/(auth)/callback.tsx` في Expo Router. احذف `wattar://auth/callback` القديم إن كنت قد أضفته؛ لا ترسل Client Secret أو مفاتيح Supabase في المحادثات.
- يستخدم تطبيق الهاتف تدفق OAuth من نوع PKCE؛ يجب أن يبقى هذا التدفق متوافقًا مع `exchangeCodeForSession` في التطبيق، ولا يكفي تغيير Redirect URLs لتبديل نوع التدفق.
- لاستعادة كلمة مرور مسؤول اللوحة المنشورة، أضف `https://<project>.vercel.app/reset-password` إلى قائمة **Redirect URLs** واستبدل النطاق بعنوان النشر الفعلي. من صفحة الدخول اضغط **نسيت كلمة المرور؟**؛ يتطلب تسليم البريد إعداد SMTP صالحًا في Supabase.

## إعداد الصوت الحي

نشر دالة `livekit-token` وحده لا يفعّل الصوت. أنشئ مشروعًا لدى LiveKit، ثم أضف `LIVEKIT_URL` و`LIVEKIT_API_KEY` و`LIVEKIT_API_SECRET` إلى **Supabase → Edge Functions → Secrets**، وتأكد من نشر الدالة على المشروع نفسه الذي يستخدمه التطبيق. لا تضع هذه القيم داخل التطبيق أو في مستودع الكود ولا ترسلها في المحادثات. إذا لم تضبط الأسرار، ستظهر الغرفة أن خدمة الصوت غير متاحة. بعد ضبطها، أعد فتح الغرفة واسمح باستخدام الميكروفون.

## الخطوة 6: بناء APK للتحميل المباشر (اختياري)

عندما تريد إصدار APK قابل للتثبيت مباشرة (بدون Expo Go):

```bash
# مرة واحدة:
npm install -g eas-cli
eas login          # أنشئ حسابًا مجانيًا على expo.dev أولًا

cd wattar-app
eas build:configure   # يضبط المشروع
eas build -p android --profile preview

# بعد البناء ستحصل على رابط تحميل APK
# شاركه مع أي شخص للتحميل والتثبيت مباشرة
```

> ملاحظة: أول مرة سيتطلب ربط حساب EAS — اضغط `projectId` في `eas build:configure` وسيضيفه تلقائيًا إلى `app.json`

## ✅ اختبار سريع للتأكد أن كل شيء يعمل

في لوحة الأدمن:
1. سجّل دخول → ستشاهد Dashboard
2. جرّب **Settings** → عدّل `daily_bonus_gold` إلى `1000` → احفظ
3. جرّب **Agents** → أنشئ وكيلًا جديدًا

في التطبيق:
1. أنشئ حسابًا بالبريد الإلكتروني أو جرّب تسجيل الدخول بأحد المزودين بعد إعدادهما.
2. أنشئ غرفة، أرسل رسالة وتحقق من وصولها الفوري.
3. جرّب الميكروفون بعد إعداد LiveKit ومنح الإذن.
4. باستخدام حسابين على جهازين، اختبر طلب الصداقة والرسالة ودعوة الغرفة والتحدي المجاني.
5. بعد ضبط FCM، فعّل الإشعارات من الإعدادات على الجهاز الثاني، أرسل رسالة إليه ثم اختبر وصول Push والتوجيه عند الضغط عليها.
6. لا تستخدم أموالًا حقيقية خلال الاختبارات.

| صفحة أدمن فارغة | افتح Console في المتصفح وتحقق من أخطاء Supabase URL |
| `supabase link` يفشل | تأكد من Project Ref الصحيح وأنك مسجّل دخول `supabase login` |
| وصول رسائل الغرف متأخر | تأكد من تشغيل `wattar-docs/patch_room_realtime.sql` مرة واحدة على قاعدة المشروع |
| لوحة الإدارة تعرض `Invalid login credentials` | دور المسؤول لا يغيّر كلمة المرور؛ استخدم زر **نسيت كلمة المرور؟** في صفحة الدخول بعد إضافة رابط `http://localhost:5174/reset-password` إلى Redirect URLs |
| الصوت غير متاح | أضف أسرار LiveKit الثلاثة إلى Edge Function Secrets وتحقق من منح إذن الميكروفون |
